- **[severity: fragile]** `scripts/0230-fdis-load.R:476`. `identical(Sys.getenv("PLACE"), "FALSE")` takes the safe path only for the exact string `FALSE`. The default, unset, is the destructive path, so `PLACE=false`, `PLACE=0` or `PLACE=no` silently runs the full placement. If `PG*` reaches a database, that run rewrites the restored `sites.rds`, `reconcile.csv` and the tracked `data/fdis_repeat_surveys.csv`, the overwrite that #246 and the new CLAUDE.md text say never to make. For the repo's `=TRUE` flags (`REMOTE`, `NO_SIGN`) a typo leaves the feature off, which is safe. Here a typo turns the protection off. Refuse any `PLACE` other than unset, `TRUE` or `FALSE` before the build starts, for example `if (!Sys.getenv("PLACE") %in% c("", "TRUE", "FALSE")) stop(...)`. (Inside round 1's fix: yes.)
