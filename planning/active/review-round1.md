## Findings

- **[bug]** R/archive.R:436-506 (`knw_archive_pull`) — the mtime ordering it documents ("Grade tables are restored before segments, whose mtime scripts/0330 holds to be later") holds only within one call. The documented restore is two steps (`PULL=TRUE`, then `GRADES=TRUE` for the tables): step 1 writes `data/compare/<key>_segments.rds`; step 2 keeps the segments (same md5, old mtime) and writes `<key>_grades.csv` with a newer mtime. `scripts/0330-compare.R:362-376` (`STAGE=maps` and `STAGE=gpkg`) then refuse "the saved segments predate their grade tables". Reproduced with the test file's mock bucket: after `knw_archive_pull(k, dest)` then `knw_archive_pull(k, dest, grades = TRUE)`, `file.mtime(segments) < file.mtime(grades)` is TRUE. Fix: after restoring a grade table, touch (`Sys.setFileTime`) that key's segments, kept or restored, to a later time.
  - **Rule:** none

- **[fragile — data loss]** R/archive.R:326-336 (`knw_archive_put` guard) with R/archive.R:529-541 (`knw_archive_undo`) — in a tokened setup (one shared folder per setup), promoting Y over promoted X makes X's objects noncurrent; undoing that promotion (`0335 RUN=replaced_*`) only appends `undone`/`promoted` rows and sends nothing, so the published run X stays noncurrent, and the bucket's 180-day noncurrent expiry under `archive/knowledge/` (research/run_archive.md) deletes it. The guard tests "is the last run archived in this folder promoted" as a stand-in for "the published run's objects are current", so after the undo an unpromoted run Z is accepted over the folder (its last archived run Y is now `undone`). Reproduced with the mock bucket: after X promoted, Y promoted, undo to X, the folder's current object is Y's, and `knw_archive_put(plan of Z, promoted = FALSE)` succeeds. Untokened setups are one folder per run and do not hit it; every build from link 0.70.0 on is tokened. An undo (or a promotion of a run whose objects are not current) needs to make the published run's versions current again, e.g. a server-side `copy-object` of each indexed version onto its key, recorded in the index.
  - **Rule:** code-check.md "A proxy is not the property"

Add `_grades_record\.csv` to `caches` (the keep check already regrades a mismatched record).
